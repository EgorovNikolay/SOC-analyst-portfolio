# Спринт 3. Расследование SSH Brute Force, бокового перемещения и эксфильтрации данных

## О проекте

В этом спринте расследовал атаку на инфраструктуру Demo Lab, которая произошла 8 марта 2025 года.

Атака началась с перебора пароля по SSH на Linux-сервер `10.0.1.254`. После успешного входа под учётной записью `service_account` злоумышленник загрузил подозрительный файл, выполнил боковое перемещение на Windows-сервер `10.0.0.15`, получил доступ к конфиденциальным документам и передал данные на внешний сервер.

Основная задача была восстановить последовательность событий по логам Linux, Windows и сетевым данным, выделить основные IoC и настроить детекты для похожих сценариев.

## Что делал

- анализировал события Linux, Windows и сетевые логи в ELK
- восстанавливал хронологию атаки
- разбирал SSH Brute Force
- искал успешный вход после серии неудачных попыток
- анализировал загрузку подозрительного файла
- разбирал боковое перемещение по SMB
- отслеживал доступ к конфиденциальным файлам
- анализировал эксфильтрацию данных
- создавал правила корреляции в Elastic Security
- собирал дашборд в Kibana
- сопоставлял действия злоумышленника с MITRE ATT&CK

## Инструменты

- **ELK Stack**: анализ `linux_auth`, `winlogs`, `networklogs`
- **Elastic Security**: правила корреляции
- **Kibana**: Lens и Visualize Library
- **MITRE ATT&CK**

## Что удалось обнаружить

### SSH Brute Force

Атака началась с внешнего IP:

`45.227.255.186`

На Linux-сервере `10.0.1.254` была серия неудачных попыток входа по SSH, после которой произошла успешная аутентификация под учётной записью:

`service_account`

### Загрузка подозрительного файла

После успешного входа на Linux-сервер был загружен файл:

`/tmp/update`

По контексту событий файл использовался после получения первоначального доступа.

### Боковое перемещение

После компрометации Linux-сервера злоумышленник выполнил переход на Windows-сервер:

`10.0.0.15`

Для доступа использовался SMB.

### Доступ к конфиденциальным данным

На Windows-сервере были зафиксированы обращения к нескольким документам:

- `C:\Shares\Financial\Annual_Report_2024.docx`
- `C:\Shares\Financial\Q4_Financial_Report.xlsx`
- `C:\Shares\Financial\Financial_Report.xlsx`
- `C:\Shares\HR\Employee_Salaries_2024.xlsx`
- `C:\Shares\HR\Employee_Reviews_2024.docx`
- `C:\Shares\Projects\Project_Roadmap_2024.xlsx`
- `C:\Shares\Projects\Project_Budget_2024.xlsx`
- `C:\Shares\Research\Product_Development_Plan.docx`

После этого был создан архив:

`data_export.zip`

### Эксфильтрация

Архив с данными был передан на внешний адрес:

`45.227.255.186:1337`

### Сокрытие следов

После основных действий были обнаружены признаки очистки логов:

- очистка логов Linux
- очистка Windows Security Log с `Event ID 1102`

## Сопоставление с MITRE ATT&CK

По ходу расследования сопоставил основные действия злоумышленника с MITRE ATT&CK:

- **T1110.001 Password Guessing**  
  Перебор пароля по SSH

- **T1059.004 Unix Shell**  
  Выполнение команд на Linux-сервере

- **T1548.003 Sudo and Sudo Caching**  
  Повышение привилегий через `sudo`

- **T1003.008 /etc/passwd and /etc/shadow**  
  Доступ к данным учётных записей Linux

- **T1021.002 SMB/Windows Admin Shares**  
  Боковое перемещение на Windows-сервер

- **T1041 Exfiltration Over C2 Channel**  
  Передача данных на внешний сервер

- **T1070.002 Clear Linux or Mac System Logs**  
  Очистка Linux-логов

- **T1070.001 Clear Windows Event Logs**  
  Очистка Windows Security Log

## Правила корреляции

В Elastic Security настроил пять правил:

1. SSH Brute Force: больше 5 неудачных попыток за 10 минут
2. успешный вход после серии неудачных попыток
3. массовый доступ к конфиденциальным файлам
4. аномальный исходящий трафик на нестандартный порт
5. цепочка событий от SSH Brute Force до эксфильтрации данных

- неудачные попытки входа по SSH

- доступ к конфиденциальным файлам
- общее количество неудачных попыток входа
- распределение источников SSH Brute Force

## Хронология атаки

Основные события:

1. `01:15:42` - начало SSH Brute Force с `45.227.255.186`
2. `01:19:15` - успешный вход под `service_account`
3. `01:24:45` - загрузка `/tmp/update`
4. `01:39:45` - боковое перемещение на `10.0.0.15` через SMB
5. `01:45:28 - 01:50:57` - доступ к конфиденциальным файлам
6. `01:52:28` - создание `data_export.zip`
7. `01:55:56` - передача данных на `45.227.255.186:1337`
8. `02:04:57` - очистка логов Linux
9. `02:15:42` - очистка Windows Security Log (`Event ID 1102`)

## Рекомендации

По результатам расследования выделил несколько основных действий:

- заблокировать `45.227.255.186`
- сменить пароль `service_account`
- проверить системы на наличие `/tmp/update`
- проверить другие хосты на похожие IoC
- включить многофакторную аутентификацию для удалённого доступа
- ограничить доступ по SSH и SMB
- использовать принцип минимальных привилегий
- использовать созданные правила корреляции для дальнейшего мониторинга
- регулярно проверять привилегированные и сервисные учётные записи
