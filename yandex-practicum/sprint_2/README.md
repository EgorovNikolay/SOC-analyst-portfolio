# Спринт 2. Расследование фишинговой атаки и компрометации контроллера домена

## О проекте

В этом спринте расследовал инцидент на хосте `adds.demo.lab` с IP `10.0.0.10`.

Атака началась с фишингового письма и вредоносного вложения `Salary_Update.exe`. После запуска файла в системе появились механизмы закрепления, сетевое соединение с C2 и признаки подготовки конфиденциальных документов к эксфильтрации.

Основная задача была в том, чтобы собрать артефакты с хоста, восстановить последовательность действий злоумышленника, определить IoC и оформить результаты расследования в TheHive.

## Что делал

- анализировал фишинговое письмо и вложение `Salary_Update.exe`
- собирал артефакты с помощью Velociraptor
- проверял процессы, сетевые соединения, задачи планировщика и реестр
- анализировал MFT и журналы событий Windows
- искал механизмы закрепления
- собирал индикаторы компрометации
- создавал кейс в TheHive
- обогащал IoC через Cortex
- проверял индикаторы в VirusTotal и AbuseIPDB
- сопоставлял действия злоумышленника с MITRE ATT&CK
- составлял рекомендации по локализации и устранению инцидента

## Инструменты

- **Velociraptor**: Pslist, LocalHashes, Netstat, TaskScheduler, BinaryHunter, EventLogs, MFT
- **TheHive**: ведение кейса и фиксация артефактов
- **Cortex**: обогащение индикаторов
- **VirusTotal**
- **AbuseIPDB**
- **MITRE ATT&CK**

## Что удалось обнаружить

### Фишинговое письмо и вредоносное вложение

В ходе анализа были выделены основные индикаторы:

- отправитель: `support@deemo.lab`
- домен: `deemo.lab`
- вложение: `Salary_Update.exe`
- MD5: `236420e9795b30db8bf9e7db4b74610e`
- SHA-1: `7fcf116e32d0685de0b766d0342d1001dc81657`
- SHA-256: `5cbf2f4b4a57bcac660c79772401077764f60e85a5123a7e311859a211abb9c1`
- C2: `101.99.90.131:443`

Домен `deemo.lab` использовался как typosquatting-вариант легитимного домена.

### Закрепление

На хосте были обнаружены два механизма закрепления:

- задача Task Scheduler `SystemHealthMonitor`
- ключ автозагрузки в реестре `WindowsUpdate`

Это позволяло вредоносной активности сохраняться после перезапуска системы.

### Сбор данных

В каталоге:

`C:\Windows\Temp\staging`

были обнаружены копии документов:

- `Salaries_2024.xlsx`
- `Budget_2025.xlsx`
- `Financial_Report.xlsx`

Их размещение в каталоге `staging` рассматривалось как подготовка данных к дальнейшей передаче.

### Сокрытие следов

В журналах были найдены события очистки логов:

- `Event ID 1102` для Security
- `Event ID 104` для System, Application и PowerShell

Это указывало на попытку удалить часть следов активности после выполнения основных действий.

## Сопоставление с MITRE ATT&CK

По ходу расследования сопоставил основные действия злоумышленника с MITRE ATT&CK:

- **T1566.001 Spearphishing Attachment**  
  Фишинговое письмо с вредоносным вложением `Salary_Update.exe`

- **T1204.002 Malicious File**  
  Запуск вредоносного файла пользователем

- **T1059.001 PowerShell**  
  Использование PowerShell для выполнения команд и запуска скриптов

- **T1053.005 Scheduled Task**  
  Закрепление через задачу `SystemHealthMonitor`

- **T1547.001 Registry Run Keys / Startup Folder**  
  Закрепление через ключ автозагрузки `WindowsUpdate`

- **T1074 Data Staged**  
  Сбор документов в `C:\Windows\Temp\staging`

- **T1071.001 Web Protocols**  
  Соединение с C2 по HTTPS

- **T1070.001 Clear Windows Event Logs**  
  Очистка журналов Windows после выполнения основных действий

## Хронология атаки

Последовательность событий выглядела так:

1. подготовка и отправка фишингового письма
2. запуск вредоносного вложения пользователем
3. выполнение PowerShell и других компонентов
4. создание задач и ключей автозагрузки
5. установка соединения с C2
6. сбор и размещение документов в `staging`
7. эксфильтрация данных
8. очистка журналов

## Рекомендации

По результатам расследования выделил несколько основных действий:

- изолировать скомпрометированный хост
- заблокировать C2 и связанный домен
- сбросить пароли затронутых учётных записей
- удалить вредоносные файлы и механизмы закрепления
- проверить аналогичные артефакты на других хостах
- усилить мониторинг PowerShell и задач планировщика
- улучшить фильтрацию фишинговых писем
- использовать AppLocker или аналогичные механизмы контроля запуска
- усилить сегментацию сети и логирование
