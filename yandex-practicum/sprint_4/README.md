# Спринт 4. Расследование подозрительной активности привилегированной учётной записи

## О проекте

В этом спринте расследовал подозрительную активность учётной записи `Demo.lab\administrator` на сервере `APPSERVER` с IP `10.0.0.10`.

20 марта 2025 года был зафиксирован вход из Германии с IP `45.14.164.3` в нерабочее время, около 03:15 по локальному времени.

После входа учётная запись использовалась для чтения конфиденциальных файлов и изменения прав доступа к папке `Finance`.

Основная задача была понять, является ли активность легитимной, найти связанные события в логах, проверить затронутые ресурсы и доработать правила детектирования для похожих сценариев.

## Что делал

- анализировал Windows-события в ELK
- проверял входы привилегированной учётной записи
- анализировал географию и время аутентификации
- искал доступ к конфиденциальным файлам
- проверял изменения прав доступа
- выделял IoC
- дорабатывал правила корреляции в Elastic Security
- исправлял плейбук реагирования
- создавал кейс в TheHive
- добавлял observables
- запускал анализ через Cortex
- сопоставлял действия с MITRE ATT&CK

## Инструменты

- **ELK Stack**: анализ событий из индекса `winlogs`
- **Elastic Security**: доработка правил корреляции
- **TheHive**: ведение кейса и работа с observables
- **Cortex**: анализ и обогащение индикаторов
- **MITRE ATT&CK**

## Что удалось обнаружить

### Подозрительный вход

Был зафиксирован вход под учётной записью:

`Demo.lab\administrator`

Источник:

`45.14.164.3`

Геолокация:

`Германия`

Время входа:

`03:15`

Сам по себе вход из необычного региона не подтверждал компрометацию, поэтому дальше проверял связанную активность учётной записи.

### Доступ к конфиденциальным файлам

После входа были зафиксированы обращения к нескольким файлам:

- `\\srv-file\Finance\Confidential\Confidential.docx`
- `\\srv-file\HR\Confidential\Confidential.docx`
- `\\srv-file\Executive\Strategy\Confidential.docx`

Эта активность усиливала подозрение на несанкционированное использование учётной записи.

### Изменение прав доступа

На папке `Finance` права были изменены на:

`Everyone:FullControl`

Это было одним из самых критичных событий в цепочке, потому что давало полный доступ к ресурсу всем пользователям.

## Индикаторы

Основные данные, которые использовал в расследовании:

- IP: `45.14.164.3`
- учётная запись: `Demo.lab\administrator`
- сервер: `APPSERVER`
- затронутые сетевые ресурсы
- изменение прав на `Everyone:FullControl`

## Сопоставление с MITRE ATT&CK

По ходу расследования сопоставил основные действия с MITRE ATT&CK:

- **T1078 Valid Accounts**  
  Использование действующей привилегированной учётной записи

- **T1222 File and Directory Permissions Modification**  
  Изменение прав доступа к папке `Finance`

- **T1083 File and Directory Discovery**  
  Работа с файловыми ресурсами и поиск доступных данных

## Правила корреляции

В рамках спринта доработал четыре правила, в которых изначально были ошибки.

### Вход в нерабочее время

Исправил условие:

`event.action: "LogonTime"`

на:

`event.code: 4624`

### Вход из необычного региона

Убрал жёсткую привязку к одной конкретной учётной записи, чтобы правило могло использоваться шире.

### Подозрительная активность с файлами

Добавил событие:

`ShareModify`

чтобы учитывать не только чтение, но и изменения файловых ресурсов.

### Изменение настроек файловых ресурсов

Исправил маску события на:

`*ShareModify*`

чтобы правило корректно срабатывало на нужные события.

## Работа с плейбуком

Также дорабатывал плейбук реагирования.

Основные изменения:

- добавил проверку рабочего графика пользователя
- добавил проверку VPN и командировок
- убрал жёсткую зависимость от одного порогового значения
- уточнил каналы связи с пользователем
- добавил шаги по изоляции системы
- добавил сохранение логов перед активными действиями
- добавил оценку воздействия инцидента
- добавил этап восстановления
- добавил разбор инцидента после завершения

## TheHive и Cortex

По результатам расследования создал кейс в TheHive:

`Подозрительное использование учётной записи администратора`

Для кейса:

- установил приоритет High
- добавил IP и учётную запись как observables
- привязал технику `T1078`
- провёл анализ индикаторов через Cortex
- после завершения расследования перевёл кейс в статус Resolved

## Рекомендации

По результатам расследования выделил несколько основных действий:

- сменить пароль привилегированной учётной записи
- отменить права `Everyone:FullControl`
- проверить другие системы на похожую активность
- включить MFA для административных учётных записей
- усилить контроль входов из необычных регионов
- контролировать входы в нерабочее время
- использовать обновлённые правила корреляции для дальнейшего мониторинга
