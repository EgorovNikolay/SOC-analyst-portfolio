# Спринт 6. Комплексное расследование компрометации корпоративной инфраструктуры

## О проекте

Итоговый проект программы.

В этом спринте расследовал многоэтапную атаку на инфраструктуру Demo Lab, которая развивалась с 30 апреля по 3 мая 2025 года.

Первоначальный доступ был получен через веб-сервер Nginx `10.0.0.22`. После этого злоумышленник закрепился на Linux-системе, повысил привилегии, получил доступ к учётным данным и перешёл во внутреннюю сеть.

Дальше атака затронула файловый сервер `10.0.0.15` и контроллер домена `10.0.0.10`. На DC была обнаружена DCSync-активность в отношении `krbtgt`. Также были выявлены сбор и передача конфиденциальных данных и последующая очистка части журналов.

Основная задача была собрать события из разных источников в единую хронологию, восстановить цепочку атаки и подготовить детекты и плейбук для похожего сценария.

## Что делал

- анализировал события в ELK / Kibana
- разбирал журналы Nginx
- анализировал Auditd и Sysmon
- работал с Windows Security Logs
- проверял события Snort, FIM и DLP
- анализировал сетевой трафик и PCAP в Wireshark
- восстанавливал хронологию атаки
- искал первоначальный вектор доступа
- анализировал закрепление и повышение привилегий
- разбирал внутреннюю разведку и боковое перемещение
- анализировал доступ к учётным данным
- проверял активность на контроллере домена
- собирал IoC
- сопоставлял действия с MITRE ATT&CK
- создавал правила обнаружения для Snort
- настраивал аудит через Auditd и Sysmon
- готовил технический и управленческий отчёты
- разрабатывал плейбук реагирования

## Инструменты

- **ELK Stack / Kibana**: поиск и анализ событий из разных источников
- **Snort**: анализ сетевой активности и правила обнаружения

- **Sysmon**: процессы, сетевые соединения и события Windows
- **Windows Security Logs**: аутентификация и действия на Windows-хостах

- **Wireshark**: анализ сетевого трафика
- **TheHive**: работа с инцидентом
- **MITRE ATT&CK**

## Что удалось обнаружить

### Первоначальный доступ

Атака началась со сканирования веб-сервера `10.0.0.22`.

Источник:

`79.143.87.233`

В логах Nginx была обнаружена эксплуатация эндпоинта:

`/nginx_status`

Через параметр `cmd` выполнялись удалённые команды, после чего на сервер был загружен вредоносный скрипт.

### Закрепление и повышение привилегий

После получения доступа на Linux-сервере были обнаружены:

- web shell
- дополнительные вредоносные файлы
- изменение `crontab`
- использование эксплойта ядра
- получение повышенных привилегий
- доступ к `/etc/shadow`

После первоначального доступа злоумышленник продолжил закрепление на хосте и повышение привилегий.

### Внутренняя разведка

На скомпрометированном сервере выполнялись команды:

- `whoami`
- `id`
- `uname`
- `netstat`
- `ps`

Также был обнаружен `smbScanner.exe`, который использовался для поиска SMB-служб во внутренней сети.

### Боковое перемещение

С веб-сервера злоумышленник перешёл на файловый сервер:

`10.0.0.15`

На Windows-системе был запущен `mimikatz`.

В событиях были обнаружены признаки доступа к `lsass.exe` и получения учётных данных.

### Компрометация Active Directory

После получения привилегированных учётных данных злоумышленник подключился по RDP к контроллеру домена:

`10.0.0.10`

Позже была зафиксирована DCSync-активность в отношении учётной записи:

`krbtgt`

Компрометация секрета `krbtgt` является критичным событием для домена, так как создаёт возможность дальнейшего злоупотребления механизмами Kerberos.

### Эксфильтрация данных

В ходе расследования были обнаружены несколько эпизодов передачи данных:

- `30.04.2025, 19:23` - передача `document_623.zip`, около 7.7 МБ, с файлового сервера на `79.143.87.233`
- `01.05.2025, 16:52` - передача `exfil_archive.tar.gz`, около 26.8 МБ, с веб-сервера на `45.140.169.16`
- `02.05.2025, 19:36` - передача `document_410.zip`, около 2.1 МБ, с контроллера домена на `45.140.169.16`

Дополнительно 3 мая в PCAP был обнаружен продолжительный TLS-поток от веб-сервера `10.0.0.22` к `45.140.169.16:443`.

Для проверки использовал:

- DLP
- сетевые журналы
- PCAP
- Wireshark
- события SIEM

### Сокрытие следов

На контроллере домена была зафиксирована очистка Windows Security Log.

Это произошло уже после основных действий злоумышленника и рассматривалось как попытка скрыть следы активности.

## Сопоставление с MITRE ATT&CK

По ходу расследования сопоставил основные действия злоумышленника с MITRE ATT&CK.

Основные техники:

- **T1595.001 Active Scanning: Scanning IP Blocks**  
  Первоначальное SYN-сканирование веб-сервера с `79.143.87.233`

- **T1046 Network Service Discovery**  
  Сканирование портов и поиск SMB-служб с помощью `smbScanner.exe`

- **T1190 Exploit Public-Facing Application**  
  Эксплуатация `/nginx_status` через параметр `cmd`

- **T1105 Ingress Tool Transfer**  
  Загрузка эксплойтов и дополнительных файлов с внешнего сервера

- **T1059 Command and Scripting Interpreter**  
  Выполнение shell-команд через скомпрометированный веб-сервер и web shell

- **T1505.003 Web Shell**  
  Создание и использование `/var/www/html/webshell.php`

- **T1053.003 Scheduled Task/Job: Cron**  
  Закрепление через изменение `crontab`

- **T1547.006 Boot or Logon Autostart Execution: Kernel Modules and Extensions**  
  Загрузка `kernel_exploit.ko`

- **T1003.008 OS Credential Dumping: /etc/passwd and /etc/shadow**  
  Получение данных учётных записей Linux из `/etc/shadow`

- **T1003.001 OS Credential Dumping: LSASS Memory**  
  Доступ к `lsass.exe` и получение учётных данных через `mimikatz`

- **T1003.006 OS Credential Dumping: DCSync**  
  Выполнение DCSync в отношении `krbtgt`

- **T1021.002 Remote Services: SMB/Windows Admin Shares**  
  Боковое перемещение на файловый сервер по SMB

- **T1021.004 Remote Services: SSH**  
  SSH-соединение между скомпрометированным сервером и внешней инфраструктурой

- **T1021.001 Remote Services: Remote Desktop Protocol**  
  RDP-подключение к контроллеру домена

- **T1078.002 Valid Accounts: Domain Accounts**  
  Использование учётных записей `webadmin` и `administrator@demo.lab`

- **T1560.001 Archive Collected Data: Archive via Utility**  
  Подготовка собранных данных в архивах перед передачей

- **T1572 Protocol Tunneling**  
  Использование туннелирования при сетевом взаимодействии

- **T1041 Exfiltration Over C2 Channel**  
  Передача данных на внешние адреса по SMTP и TLS

- **T1071.004 Application Layer Protocol: DNS**  
  DNS-запросы к доменам C2-инфраструктуры

- **T1070.001 Indicator Removal: Clear Windows Event Logs**  
  Очистка Windows Security Log на контроллере домена

## Правила обнаружения

### Snort

Подготовил правила для обнаружения:

- сканирования портов
- попыток command injection через Nginx
- признаков command injection в HTTP-запросах

### Auditd

Настроил аудит для событий, связанных с:

- изменением `crontab`
- доступом к критичным системным файлам
- запуском подозрительных бинарных файлов
- изменением конфигурации Linux

### Sysmon

Настроил мониторинг:

- создания процессов
- сетевых соединений
- доступа к `lsass.exe`
- запуска подозрительных утилит
- создания и изменения файлов

## Хронология атаки

Основные события:

1. `30.04.2025, 07:07` - эксплуатация веб-приложения Nginx
2. `30.04.2025, 08:53` - закрепление и повышение привилегий на Linux-сервере
3. `30.04.2025, 15:42` - боковое перемещение на файловый сервер
4. `30.04.2025, 18:08` - получение учётных данных с помощью `mimikatz`
5. `30.04.2025, 19:23` - начало эксфильтрации данных
6. `01.05.2025, 01:45` - RDP-подключение к контроллеру домена
7. `01.05.2025, 04:17` - DCSync в отношении `krbtgt`
8. `01.05.2025, 18:59` - очистка журнала безопасности контроллера домена
9. `02.05.2025, 19:36` - дальнейшая передача данных из инфраструктуры
10. `03.05.2025, 13:33` - продолжительный TLS-трафик от `10.0.0.22` к `45.140.169.16:443`

## Ограничения расследования

Для рабочих станций `10.0.0.30-33` в SIEM отсутствовали Windows Security Logs.

Из-за этого не удалось однозначно подтвердить или исключить их компрометацию. Эти хосты рассматривались как потенциально затронутые до проведения дополнительной проверки.

## Рекомендации

По результатам расследования выделил несколько основных действий:

- изолировать скомпрометированные системы
- заблокировать выявленные IoC
- сменить пароли скомпрометированных и привилегированных учётных записей
- провести двойную смену пароля `krbtgt` по процедуре восстановления Active Directory
- удалить web shell, вредоносные файлы и другие механизмы закрепления
- проверить остальные системы на связанные артефакты
- восстановить затронутые системы из доверенных резервных копий при необходимости
- ограничить административные протоколы между сегментами сети
- усилить мониторинг привилегированных учётных записей
- использовать Snort, Auditd и Sysmon для обнаружения похожей активности
- контролировать передачу больших объёмов данных через DLP и сетевой мониторинг
